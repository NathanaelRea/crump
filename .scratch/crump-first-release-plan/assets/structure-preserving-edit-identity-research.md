# Structure-Preserving Edit and Identity Research

## Conclusion

No reviewed system treats a syntax-node object as durable source identity. Roslyn, SwiftSyntax, Rowan, and tree-sitter use node identity to distinguish occurrences or reuse work within one or related in-memory trees. Their documented guarantees stop short of arbitrary reparse, reload, and process restart. For Crump, "stable source identity" should therefore be split into three contracts:

1. **Snapshot identity:** this exact syntax occurrence in one parsed revision.
2. **Edit-chain identity:** the best-effort correspondence of an occurrence across related in-memory revisions.
3. **Durable domain identity:** the identity of a user-authored musical entity across rename, move, reload, and restart.

The first two should be ephemeral implementation details. The third must be recoverable from authoritative source: either an explicit source-carried ID or, where rename stability is not required, a declared semantic name/path.

## Documented Facts

### Lossless and immutable tree designs

- **Roslyn:** syntax trees are immutable snapshots, reuse underlying nodes when producing new versions, and are full fidelity: whitespace, comments, directives, malformed input, and exact literal spelling are represented and can be round-tripped ([syntax model](https://learn.microsoft.com/en-us/dotnet/csharp/roslyn-sdk/work-with-syntax#syntax-trees)). Trivia is attached to tokens as leading or trailing trivia ([syntax trivia](https://learn.microsoft.com/en-us/dotnet/csharp/roslyn-sdk/work-with-syntax#syntax-trivia)). The public red `SyntaxNode` stores parent and position over an internal green node; `IsIncrementallyIdenticalTo` means two red nodes reference the same reused green node, even though parent and position may differ ([`SyntaxNode` source](https://github.com/dotnet/roslyn/blob/main/src/Compilers/Core/Portable/Syntax/SyntaxNode.cs#L218-L235)). Roslyn can format only annotated nodes or specified spans rather than a whole document ([`Formatter` API](https://learn.microsoft.com/en-us/dotnet/api/microsoft.codeanalysis.formatting.formatter)).
- **Roslyn annotations:** `SyntaxAnnotation` adds information to an immutable syntax element by creating a new element ([API](https://learn.microsoft.com/en-us/dotnet/api/microsoft.codeanalysis.syntaxannotation)); its current implementation contains only in-memory `Kind` and `Data`, and equality remains object identity ([source](https://github.com/dotnet/roslyn/blob/main/src/Compilers/Core/Portable/Syntax/SyntaxAnnotation.cs)). Green-node annotations are held in a `ConditionalWeakTable`, not emitted as source text ([`GreenNode` source](https://github.com/dotnet/roslyn/blob/main/src/Compilers/Core/Portable/Syntax/GreenNode.cs#L32-L35)).
- **SwiftSyntax:** the package describes its tree as a source-accurate representation ([README](https://github.com/swiftlang/swift-syntax#swift-syntax)). Raw nodes are immutable, freely shareable, and have no identity; writing a raw tree is source-accurate and includes token trivia ([`RawSyntax` source](https://github.com/swiftlang/swift-syntax/blob/main/Sources/SwiftSyntax/Raw/RawSyntax.swift)). Replacing a child copies the path to the root and creates a new tree/arena ([`Syntax` source](https://github.com/swiftlang/swift-syntax/blob/main/Sources/SwiftSyntax/Syntax.swift)).
- **SwiftSyntax identity has an unusually explicit limit:** `SyntaxIdentifier` is unique for a node, but modifying any node copies the tree and changes **all** node IDs. Its transferable index is valid across another tree only when trees are exactly equivalent or when mutation only replaces tokens without inserting or removing nodes ([`SyntaxIdentifier` source](https://github.com/swiftlang/swift-syntax/blob/main/Sources/SwiftSyntax/SyntaxIdentifier.swift)).
- **Rowan/rust-analyzer:** Rowan is a generic library for lossless syntax trees ([README](https://github.com/rust-analyzer/rowan)). rust-analyzer documents that every token carries its full text, original text is recovered by concatenating tokens, and whitespace/comments are retained; green trees are immutable and structurally shared ([syntax-tree guide](https://rust-analyzer.github.io/book/contributing/syntax.html#greennode)). `SyntaxNode` adds parent, absolute offset, and occurrence identity; the guide says comparing nodes from different trees does not make sense ([identity discussion](https://rust-analyzer.github.io/book/contributing/syntax.html#syntax-nodes)). Current Rowan equality uses the green allocation pointer plus absolute offset, while cursor nodes are explicitly transient ([`cursor.rs`](https://github.com/rust-analyzer/rowan/blob/master/src/cursor.rs)). `replace_with` returns a green tree differing at one node with work proportional to tree depth ([API](https://docs.rs/rowan/latest/rowan/api/struct.SyntaxNode.html#method.replace_with)).
- **tree-sitter:** editing an old tree updates ranges, then reparsing with that tree produces a new tree that internally shares structure; separately retained node values must also receive the edit if they will continue to be used ([editing guide](https://tree-sitter.github.io/tree-sitter/using-parsers/3-advanced-parsing.html#editing)). A node ID is unique within one tree and remains equal across old/new trees only if that node was reused. The API explicitly warns that an unchanged marker does not guarantee reuse ([`Node::id`](https://docs.rs/tree-sitter/latest/tree_sitter/struct.Node.html#method.id)). Tree-sitter produces concrete trees containing punctuation, and comments can be represented as extra nodes ([basic parsing](https://tree-sitter.github.io/tree-sitter/using-parsers/2-basic-parsing.html#named-vs-anonymous-nodes), [`Node::is_extra`](https://docs.rs/tree-sitter/latest/tree_sitter/struct.Node.html#method.is_extra)); node text is obtained from the separate source buffer by range ([`Node::utf8_text`](https://docs.rs/tree-sitter/latest/tree_sitter/struct.Node.html#method.utf8_text)).

### What survives

| Mechanism | Unrelated edit | Edit/rename of target | Full reparse/reload | Process restart |
|---|---|---|---|---|
| Roslyn green reuse | May survive when incremental parser reuses the node | No guarantee; changed target normally gets a new green node | No documented guarantee | No |
| Roslyn `SyntaxAnnotation` | Can follow tree transformations that preserve the annotated element | Only if the transformation explicitly carries it | No source representation; no documented reparse guarantee | No |
| SwiftSyntax `SyntaxIdentifier` | No: any tree modification changes all IDs | No | No; only `SyntaxIndexInTree` can be reapplied under the narrow documented structural conditions | Only the transferable index under those same conditions, not the full ID |
| Rowan `SyntaxNode` equality | Shared green pointer plus unchanged offset can coincide, but cross-tree comparison is not a supported identity contract | No dependable guarantee | No documented guarantee | No |
| tree-sitter `Node::id` | Yes only when incremental parsing actually reuses the node | No reuse guarantee | No documented guarantee without the related old tree | No |
| Semantic qualified name/path | Usually | No: rename or containing-path change changes the name | Yes if declarations and language interpretation remain the same | Yes under the same condition |
| Explicit ID in authoritative source | Yes | Yes if the edit preserves it | Yes | Yes |

The syntax-node rows are direct summaries of the cited guarantees. The last two rows are **inference**: names are recomputed from declarations, while source-carried IDs are reparsed as ordinary authored data.

## Implications for Crump

### Preservation

**Documented fact:** full-fidelity trees make comments and formatting addressable rather than discarded, but immutability or losslessness alone does not require an editor to preserve them. Roslyn exposes both whole-tree and span/annotation-scoped formatting, while Rowan exposes subtree replacement; tree-sitter retains source ranges rather than owning a source-accurate printable tree.

**Inference:** Crump should treat a structured operation as a minimal source patch, not as "deserialize AST, modify model, print file." Resolve a typed construct, replace only the smallest token or expression range required, and leave every byte outside the patch untouched. Apply local formatting only to newly synthesized syntax where necessary. This gives a testable rule: outside declared edit ranges, old and new bytes are identical.

For procedural expressions, a scalar control must not replace an expression subtree merely because the expression currently evaluates to a scalar. A first-release command should either edit a recognized literal leaf, perform an explicitly expression-aware rewrite, or report that the construct is source-only. This is an inference from Crump's non-flattening requirement, not a guarantee supplied by any syntax library.

### Identity choices

- **Ephemeral syntax identity** is useful for caches, selections, diagnostics, and mapping an open TUI view through nearby edits. It is cheap and invisible in source, but it cannot satisfy rename/reload/restart identity.
- **Semantic names/qualified paths** are human-readable and naturally source-controlled. They are suitable when rename intentionally means a new key, but are not rename- or move-stable and need language rules for scope, shadowing, overloads, and references. Roslyn likewise separates syntax from symbols because syntax alone cannot determine what a name references ([semantic model overview](https://learn.microsoft.com/en-us/dotnet/csharp/roslyn-sdk/work-with-syntax#working-with-semantics)).
- **Explicit source IDs** are the only reviewed option that straightforwardly meets arbitrary reparse/restart plus rename stability. The costs are visible syntax, duplicate-ID handling after copy/paste, merge conflicts, ID generation policy, and a decision about whether cloning preserves or regenerates identity. These costs are product-design inferences, not claims from the reviewed libraries.

## First-Release Prototype Recommendation

1. **Use a lossless Rust CST, with Rowan as the leading prototype candidate.** Keep every token, comment, whitespace run, error token, and procedural expression. Do not make Rowan node equality part of Crump's persisted or public model.
2. **Make text the edit substrate.** Parse a source revision, resolve a typed target, check the expected revision/kind/current text, and emit one ordered set of non-overlapping text replacements. Reparse and validate the result. Never regenerate an enclosing declaration or file merely to change one value.
3. **Use a hybrid locator.** During a session, use `(revision, file, range, syntax kind/field role)` and map/re-resolve it after edits. For references and user-visible selection, resolve semantic declared names against the current revision. Introduce explicit source IDs only for domain entities that demonstrably require identity across rename/reorder/reload (for example tracks or graph nodes), not for every syntax node, token, parameter occurrence, or expression.
4. **Define rename as a semantic transaction.** Resolve the declaration and references before editing, emit all text replacements in one transaction, preserve any explicit domain ID, and reject stale or ambiguous targets. A qualified name is a lookup key, not the entity's durable identity.
5. **Unify direct and structured undo.** One user action should produce one transaction containing all source changes and selection/effect metadata. CodeMirror documents this model directly: a transaction may contain any number of document changes, and its history stores inverse changes; history boundaries can isolate an action ([transactions](https://codemirror.net/docs/ref/#state.Transaction), [history source](https://github.com/codemirror/commands/blob/main/src/history.ts)). VS Code similarly describes a complex editor edit as one transaction and exposes undo stops around it ([`TextEditorEdit` source](https://github.com/microsoft/vscode/blob/main/src/vscode-dts/vscode.d.ts)). Store enough inverse text (or immutable before/after text snapshots) that undo restores exact bytes, including trivia and expressions.
6. **Prototype acceptance tests:** literal parameter edit; semantic rename; point-automation edit; refusal or expression-aware edit of procedural automation; comments and unusual spacing adjacent to targets; malformed neighboring source; stale-target conflict; undo/redo byte equality; reload identity for explicitly identified entities. Assert byte identity outside edit ranges and exact restoration after undo.

This deliberately avoids promising durable syntax identity in release one. It proves the user-facing contract that matters: source remains authoritative and readable, targeted edits preserve unrelated material, procedural forms are not flattened, and every structured operation is exactly undoable.
