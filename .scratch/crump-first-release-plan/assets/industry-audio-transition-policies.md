# Industry Audio Transition Policies

## Finding

There is no evidenced industry-wide rule such as "always wait for zero," "always crossfade," or "always switch on a beat." The primary sources instead specify different controls for automation, running-source replacement, clip edges, and musical launch timing ([VST 3 automation](https://steinbergmedia.github.io/vst3_dev_portal/pages/Technical+Documentation/Parameters+Automation/Index.html#automation-playback), [SuperCollider `NodeProxy`](https://doc.sccode.org/Classes/NodeProxy.html), [Ableton clip fades](https://www.ableton.com/en/live-manual/12/arrangement-view/#audio-clip-fades-and-crossfades), [Ableton launch quantization](https://www.ableton.com/en/live-manual/12/launching-clips/#clip-launch-quantization)). Standards commonly define when change data reaches processing, while applications and plug-ins choose whether to step, ramp, crossfade, quantize, preserve state, or restart ([Web Audio processing model](https://www.w3.org/TR/2021/REC-webaudio-20210617/#processing-model), [CLAP parameters](https://github.com/free-audio/clap/blob/main/include/clap/ext/params.h)).

## 1. Continuous parameter changes

- **Timing is standardized more often than smoothing.** VST 3 hosts provide ordered automation points with offsets inside the processing block, sufficient for sample-accurate reconstruction, but Steinberg explicitly leaves the processing/accuracy cost to the plug-in implementation ([VST 3, Automation Playback](https://steinbergmedia.github.io/vst3_dev_portal/pages/Technical+Documentation/Parameters+Automation/Index.html#automation-playback)). CLAP likewise timestamps every event with a sample offset and requires input events to be sorted, while allowing a plug-in to choose smoothing for note-expression streams ([CLAP `events.h`](https://github.com/free-audio/clap/blob/main/include/clap/events.h)). These are automatic transport/API rules, not universal ramp rules.
- **Ramps are explicit controls.** Web Audio's `AudioParam` supplies immediate set, linear ramp, exponential ramp, target, and curve operations; its performance guidance warns that directly changing gain can click and recommends a short exponential transition, but the author selects and schedules it ([Web Audio `AudioParam`](https://www.w3.org/TR/2021/REC-webaudio-20210617/#AudioParam), [AudioParam Transitions](https://www.w3.org/TR/2021/REC-webaudio-20210617/#audioparam-transitions)).
- **A live-coding system also distinguishes set from smoothing.** SuperCollider `NodeProxy.set` changes controls, `xset` crossfades into new settings using the proxy's configurable `fadeTime`, and `lag` assigns per-control lag ([NodeProxy: setting synth controls](https://doc.sccode.org/Classes/NodeProxy.html#Setting%20synth%20controls)). Smoothing is therefore user-selected, not silently universal.
- **Structural parameters may require restart instead of smoothing.** CLAP says an automatable parameter that changes internal processing structure, such as maximum delay or FFT size, should request host restart and apply the change after reactivation ([CLAP `params.h`](https://github.com/free-audio/clap/blob/main/include/clap/ext/params.h)).

## 2. Graph/topology or running-process replacement

- **JITLib makes replacement overlap an explicit, configurable policy.** `NodeProxy` is designed for replacing and recombining running sources; `fadeTime` controls the overlap, `quant` can defer replacement to a beat grid, and the current first-party source sets a 20 ms default fade ([NodeProxy description, `fadeTime`, and `quant`](https://doc.sccode.org/Classes/NodeProxy.html), [NodeProxy source](https://github.com/supercollider/supercollider/blob/develop/SCClassLibrary/JITLib/ProxySpace/NodeProxy.sc)). Source replacement starts the new synth and releases/removes the old one; the source shows old groups/buses being freed only after fade time plus server latency ([NodeProxy source](https://github.com/supercollider/supercollider/blob/develop/SCClassLibrary/JITLib/ProxySpace/NodeProxy.sc)). The overlap and delayed cleanup are automatic implementation behavior once configured.
- **JITLib's automation has defined exceptions.** It generates a fade envelope for ordinary audio/control outputs, but may free without fading for scalar output, trusts a user-provided self-freeing envelope, and lets a user-provided `fadeTime` argument consume the proxy setting ([JITLib fading tutorial](https://doc.sccode.org/Tutorials/JITLib/jitlib_fading.html)). Thus even this replacement-oriented system does not claim one transition for every graph.
- **Real-time graph publication can be separated from transition semantics.** The Web Audio Recommendation defines a control thread, rendering thread, control-message queue, and graph rendering in quanta; graph mutations are communicated as ordered control messages rather than by having application code mutate the rendering graph concurrently ([Control Thread and Rendering Thread](https://www.w3.org/TR/2021/REC-webaudio-20210617/#control-thread-and-rendering-thread), [Rendering an Audio Graph](https://www.w3.org/TR/2021/REC-webaudio-20210617/#rendering-loop)). This is automatic implementation policy, but the specification does not mandate crossfading arbitrary connect/disconnect operations.
- **First-party Rust source demonstrates publication plus off-render retirement.** FunDSP splits a dynamic `Net` into a mutable frontend and "real-time friendly" backend, preallocates a revision before enqueueing it, returns replaced networks/units through a second queue, and drops returned versions in frontend `commit`; it separately offers immediate `replace` and configurable `crossfade` operations ([FunDSP `net.rs`](https://github.com/SamiPerttu/fundsp/blob/master/src/net.rs)). The handoff/retirement mechanism is automatic; the audible replacement policy is selectable.

## 3. Sample/clip cuts and loop boundaries

- **DAW edge protection is often a preference-backed default.** Ableton Live's Session clips can apply a signal-dependent 0-4 ms start/end fade to avoid edge clicks. The clip toggle is enabled by default only when the global "Create Fades on Clip Edges" setting is enabled ([Live 12, Clip Start and End Fades](https://www.ableton.com/en/live-manual/12/clip-view/#clip-start-and-end-fades)).
- **Arrangement edits remain editable semantics.** With that preference enabled, Live creates 4 ms edge fades and 4 ms crossfades between adjacent clips; users can change fade duration/curve, create/delete fades, or disable the preference ([Live 12, Audio Clip Fades and Crossfades](https://www.ableton.com/en/live-manual/12/arrangement-view/#audio-clip-fades-and-crossfades)). This is an automatic default governed by user configuration, not a fixed engine invariant.
- **Loop handling is not reducible to edge fades.** Live does not allow Arrangement fades to cross clip loop boundaries. In Beats warp mode it can instead loop transient segments from a nearby zero crossing and exposes a Transient Envelope whose higher values can smooth clicks while lower values create gating ([Live 12, Audio Clip Fades and Crossfades](https://www.ableton.com/en/live-manual/12/arrangement-view/#audio-clip-fades-and-crossfades), [Beats Mode](https://www.ableton.com/en/live-manual/12/audio-clips-tempo-and-warping/#beats-mode)). The system uses different, configurable policies for clip edges and internal repetition.

## 4. Musical/quantized boundaries

- **Quantization controls onset, not waveform continuity.** SuperCollider `NodeProxy.quant` schedules source replacement on a beat grid, independently of `fadeTime`; its examples use two-beat replacement while the general `Quant` model exposes grid, phase, and timing offset ([NodeProxy `quant`](https://doc.sccode.org/Classes/NodeProxy.html#-quant), [SuperCollider `Quant`](https://doc.sccode.org/Classes/Quant.html)).
- **DAW launch timing is user-configurable and optional.** Ableton's per-clip launch quantization can be `None`, inherit `Global`, or use its own interval; Legato mode can preserve the prior clip's beat-time position even with quantization disabled ([Live 12, Clip Launch Quantization and Legato Mode](https://www.ableton.com/en/live-manual/12/launching-clips/#clip-launch-quantization)). Live separately exposes a Clip Update Rate that quantizes when running-clip property edits take effect ([Live 12, Clip Defaults and Update Rate](https://www.ableton.com/en/live-manual/12/clip-view/#clip-defaults-and-update-rate)). These are musician-facing timing policies, not automatic click suppression.

## Implication for Crump

For the current safe-graph-replacement planning ticket, carry forward only this mechanism and fallback:

1. **Publication:** build and validate revisions off the audio callback; publish through a bounded, non-blocking handoff; let the callback keep the active revision when no complete replacement is available. Web Audio's control/render separation and FunDSP's frontend/backend commit model support this separation without implying identical internals ([Web Audio processing model](https://www.w3.org/TR/2021/REC-webaudio-20210617/#processing-model), [FunDSP `net.rs`](https://github.com/SamiPerttu/fundsp/blob/master/src/net.rs)).
2. **Retirement:** return superseded graphs through bounded callback-safe bookkeeping and destroy them off-callback. FunDSP's return queue and JITLib's cleanup after overlap/latency provide direct precedents for deferring retirement beyond the replacement instant ([FunDSP `net.rs`](https://github.com/SamiPerttu/fundsp/blob/master/src/net.rs), [NodeProxy source](https://github.com/supercollider/supercollider/blob/develop/SCClassLibrary/JITLib/ProxySpace/NodeProxy.sc)). Publication must define bounded backpressure/coalescing on the producer side rather than allowing the callback to wait.
3. **Fallback transition:** retain a short, bounded crossfade as the provisional fallback when no edit-specific rule exists. It has stronger production precedent than a hard swap, and unlike waiting for a zero crossing it has a fixed completion bound; no source supports one universal duration, so keep the duration measurable and provisional ([NodeProxy default/configurable fade](https://doc.sccode.org/Classes/NodeProxy.html#-fadeTime), [Live edge fades](https://www.ableton.com/en/live-manual/12/clip-view/#clip-start-and-end-fades), [FunDSP configurable `crossfade`](https://github.com/SamiPerttu/fundsp/blob/master/src/net.rs)).

Do **not** turn that fallback into Crump's semantic contract. The later runtime-transition contract should classify parameter edits, topology edits, sample/loop edits, and musical scheduling, then decide state migration, tail preservation, restart, ramp shape/duration, quantization, and explicit opt-outs per class. SuperCollider's independent `fadeTime`/`quant` controls, Ableton's separate edge-fade/launch settings, and CLAP's restart rule for structural parameters show that these are product and DSP semantics, not consequences of safe publication ([NodeProxy](https://doc.sccode.org/Classes/NodeProxy.html), [Ableton clip fades](https://www.ableton.com/en/live-manual/12/clip-view/#clip-start-and-end-fades), [Ableton launch quantization](https://www.ableton.com/en/live-manual/12/launching-clips/#clip-launch-quantization), [CLAP `params.h`](https://github.com/free-audio/clap/blob/main/include/clap/ext/params.h)).
