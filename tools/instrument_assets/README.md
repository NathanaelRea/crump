# Instrument asset generation

The [example instrument library](../../examples/instruments/README.md) includes its generated WAVs. Python is needed only to rebuild those assets, not to play them.

```bash
uv run tools/instrument_assets/build.py --only finger-bass egg-shaker --output renders/rebuilt-instruments
```

Omit `--only` to build all banks. The default output is the example library itself; existing media with different bytes is never replaced. Use a separate output directory when changing a recipe or generator. Native acoustic modules are copied unchanged and receive an audition Project; their sound is generated by Crump.

`recipe.json` contains the numerical model, optional treatment, seed base and render horizon. The generator uses pinned NumPy/SciPy, float64 processing and seeded PCG64 at 48 kHz. Membranes, damped bars, string delay loops, collision gestures and hammer/tine models produce source audio without recorded input. Treatments are deterministic filtering, quantization, echo, tremolo, reversal or decay shaping.

Hard-layer peak normalization is shared with its soft layer. Media is mono PCM16, with silent suffixes removed below the quantization floor and an endpoint fade. Pitched banks span eight roots and two velocity layers; percussion uses two velocity layers and two deterministic round robins. `assets.json` records exact WAV hashes, recipe and generator hashes, seeds, gain and frame counts. Treatments retain their full generating recipe rather than requiring a hidden dry sample.

Reproduction is deterministic within the same numerical environment. Different CPU/library implementations can change final rounding; compare manifest hashes before replacing distributed media. Example sources and generated audio use the repository's MPL-2.0 license.

## Verification

Build the CLI, then validate and render the distributed audition Projects:

```bash
cargo build --release --locked --bin crump
python3 tools/instrument_assets/verify.py --render --workers 2
python3 -m unittest discover -s tools/instrument_assets -p 'test_*.py'
```

The verifier publishes each example through the normal History seam, checks the exact Active Revision, plans its render and rejects silent, clipped or non-finite output. Reports and renders go to `renders/instrument-verification`. Use a fresh `--output` directory for another render pass; existing renders are not replaced. Omit `--render` for source/media validation and publication only.

`crump check` also evaluates a separate 30–60-second Reference Musical Sketch contract. These shorter instrument auditions intentionally do not satisfy that contract; verification records the result while requiring full Project validation. The tests additionally check catalog completeness, global ID uniqueness, generator/recipe/media hashes, and importing several native and sample instruments into a fresh Project with the copy helper.
