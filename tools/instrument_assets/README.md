# Instrument asset generation

The [example instrument library](../../examples/instruments/README.md) commits its recipes, modules and media hashes, not the WAVs. Generate the samples once after cloning, and again after pulling instrument changes:

```bash
uv run tools/instrument_assets/build.py --setup
```

Setup writes only missing or outdated samples, in parallel (`--jobs`), and checks each against the SHA-256 in its `assets.json`. It never edits a module or manifest; if this machine's NumPy/SciPy build rounds differently and a sample does not match, it stops with an error instead of changing the instrument. Native acoustic instruments need no media.

To change instruments, rebuild them:

```bash
uv run tools/instrument_assets/build.py --only finger-bass egg-shaker --output renders/rebuilt-instruments
```

Omit `--only` to build all banks. The default output is the example library itself; existing media with different bytes is never replaced. Use a separate output directory when changing a recipe or generator. Native acoustic modules are copied unchanged and receive an audition Project; their sound is generated by Crump.

`recipe.json` contains the numerical model, optional treatment, seed base and render horizon. The generator uses pinned NumPy/SciPy, float64 processing and seeded PCG64 at 48 kHz. Membranes, damped bars, string delay loops, collision gestures and hammer/tine models produce source audio without recorded input. Bowed strings use a stick-slip waveguide (after the STK Bowed model) bowed at a steady pitch, with vibrato applied afterwards by 4× oversampled resampling (modulating the waveguide length disturbs the stick-slip motion audibly high up the range), through fitted instrument bodies, and the choir uses glottal pulses through cascaded vocal-tract formants. Winds and brass use an additive harmonic source read through a fixed formant response, so vibrato moves each partial through the resonances. Brass partials brighten with dynamic level. Sections sum independently detuned players. Separate models cover timpani, the concert snare, castanets, the triangle, and plates (tam-tam and suspended cymbal) whose upper modes bloom after the strike. The organ sums separately tuned pipe ranks. The expansion adds an analog drum-machine voice (swept sine, tuned partials, click, filtered noise and clusters of band-limited square waves), tuned membranes with an optional pitch contour (toms, talking drum), struck modal bodies with measured mode ratios and slowly beating pairs (pans, bowls, gamelan, music box, wood), layered models (a clap with a room tail, a ride bell with wash, an opera gong that bends upward), plucked strings with courses, bridge buzz (sitar jawari, shamisen sawari), sympathetic strings and an amp and cabinet, a tonewheel organ with percussion and key click, a prepared piano, a lip-buzzed drone that moves between two vowels (didgeridoo), a wheel-bowed hurdy-gurdy over fixed drones, a friction drum (cuíca), a scraped gourd (guiro) and swept chimes (mark tree). Bowed strings can play tremolo. Treatments are deterministic filtering, quantization, echo, tremolo, reversal, decay shaping, a rotary speaker or tape replay (wow, flutter, a narrow head and hiss).

Hard-layer peak normalization is shared with its soft layer. Media is PCM16, mono except where a recipe sets `stereo` (the string section places its players across the stage), with silent suffixes removed below the quantization floor and an endpoint fade. Pitched banks span eight roots (or the recipe's own `roots` and key `range`) and two velocity layers; percussion uses two velocity layers and two deterministic round robins. Each `instrument.crump` declares its own media, so the audition `project.crump` only imports it. Zones state their asset, keys, velocity range, root and any loop, and leave the other clauses at their defaults; a percussion key's two round robins are overlapping zones that the multisample node chooses between. `assets.json` records exact WAV hashes, recipe and generator hashes, seeds, gain and frame counts. Treatments retain their full generating recipe rather than requiring a hidden dry sample. A recipe `release` builds a module whose amplitude envelope drives the multisample gain, giving sustained one-shot samples a Note Off release. A recipe `loop` of start, end and crossfade seconds adds a zone sustain loop; the builder first evens out slow level changes inside the loop (at most 6 dB, over a `loop_leveling` window of 120 ms or a recipe's own) so no swell repeats on every pass, then moves each end up to 25 ms to where the crossfade windows correlate best and records the frames in `assets.json`. A recipe `audition` note selects the orchestral audition phrases. A recipe `fixed_keys` range maps unpitched banks in five-key groups rooted at their centres, so no key moves more than two semitones from the recorded pitch. An unpitched recipe's `strokes` instead render one bank per stroke (a darbuka's doum and tek), each with its own params and key range in the same five-key groups. A recipe `reference_eq` applies a smooth minimum-phase correction fitted against reference recordings (below).

Reproduction is deterministic within the same numerical environment. Different CPU/library implementations can change final rounding, which is why setup compares every sample with its manifest hash. Example sources and generated audio use the repository's MIT license.

## Fitted string bodies

The bowed recipes share their bowing settings through `"extends": "bowed"`, which starts from [`shared/bowed.json`](shared/bowed.json); a recipe's own keys and params win. Each names its body curve, such as `"eq": "cello"`, read from [`shared/bodies`](shared/bodies) as `[hz, dB]` points; the string section's `eq_registers` blends the four bodies by register. `assets.json` records the hash of every shared file a bank read, so the library test notices a changed family or body.

The violin, cello and contrabass bodies are fitted to recordings rather than chosen by hand. The viola uses the violin body scaled 15% lower in frequency. `fit_bowed.py` repeats the fit and reports the held-out error; `--write` replaces the shared body curves with the new fits:

```bash
uv run tools/instrument_assets/fit_bowed.py --references ~/iowa-mis-strings \
  --instrument solo-violin cello contrabass --smoothing 5 --write
```

Rebuilding then changes media, so build to a fresh `--output` directory or remove the affected `media` folders first.

References are [University of Iowa MIS](https://theremin.music.uiowa.edu/MIS.html) arco recordings in their original file names, such as `Violin.arco.mf.sulD.D4B4.mono.aif`. They are analysis input only and are not distributed. Each note's pitch is detected from the audio and must fall within its file's labelled range. The body is the median difference between model and reference partial levels in 1/24-octave bins, pooled over notes and dynamics, capped at ±20 dB and level-neutral between 300 Hz and 3 kHz. Even notes fit it; odd notes score it. Without the cap, a fit can hide a model fault: an early fit added 35 dB at 349 Hz to cover a bow that slipped twice per cycle. The bowing now stays inside the Helmholtz region for every note.

## Reference recordings

[`references.json`](references.json) lists freely licensed recordings to compare the expansion instruments against: isolated notes from the [University of Iowa MIS](https://theremin.music.uiowa.edu/MIS.html) and [VSCO-2 CE](https://github.com/sgossner/VSCO-2-CE) where they exist, otherwise [Wikimedia Commons](https://commons.wikimedia.org/) recordings with their own licences. They are listening and analysis aids only, downloaded locally and never committed or distributed. Fetching needs ffmpeg:

```bash
uv run tools/instrument_assets/references.py --fetch
uv run tools/instrument_assets/references.py --compare
```

`--fetch` downloads each source once, slices the clip in `references.json` and writes it to `renders/instrument-references` as 48 kHz mono. `--compare` detects each clip's pitch, renders the model at that note and records sixth-octave long-term spectra, 20 dB decay and spectral centroid for both in `report.json`, which the [instrument player](../instrument_player/README.md) shows beside each instrument. A clip's `hz` overrides the detected pitch; a `stroke` picks which stroke of a two-stroke recipe it compares against.

The comparison guided the recipes. Mode ratios for the singing bowl, gamelan, agogô, music box, log drum and ride bell, for example, are the partials measured in their references. `--fit ID --write` stores a `reference_eq` in a recipe: the smoothed mean spectral difference, capped at ±8 dB per fit and level-neutral where the instrument is loudest. Fits are only used where the reference is an isolated note of the same instrument; a performance recorded in a room teaches the model the room. Rebuild the bank afterwards.

## Verification

Build the CLI, then validate and render the distributed audition Projects:

```bash
cargo build --release --locked --bin crump
python3 tools/instrument_assets/verify.py --render --workers 2
python3 -m unittest discover -s tools/instrument_assets -p 'test_*.py'
```

The verifier publishes each example through the normal History seam, checks the exact Active Revision, plans its render and rejects silent, clipped or non-finite output. Reports and renders go to `renders/instrument-verification`. Use a fresh `--output` directory for another render pass; existing renders are not replaced. Omit `--render` for source/media validation and publication only.

`crump check` also evaluates a separate 30–60-second Reference Musical Sketch contract. These shorter instrument auditions intentionally do not satisfy that contract; verification records the result while requiring full Project validation. The tests additionally check catalog completeness, global ID uniqueness, generator/recipe/media hashes, and importing several native and sample instruments into a fresh Project with the copy helper.
