# Architecture Overview

## Fixed constraints

- Rust is the implementation language.
- Ratatui is the human client, while Project, authoring, persistence, engine, realtime, and render modules remain terminal-independent ([ADR 0007](../adr/0007-terminal-first-client-boundary.md)).
- The Linux baseline is native PipeWire, not a JACK compatibility layer ([ADR 0002](../adr/0002-native-pipewire-linux-baseline.md)).
- Readable declarative source is authoritative ([ADR 0010](../adr/0010-small-declarative-project-language.md)); Production Views make checked structure-preserving replacements ([ADR 0001](../adr/0001-structure-preserving-source-edits.md)).
- Invalid Candidate Revisions never partially or implicitly replace Active audio.
- Playback and offline rendering share compiled schedule, effective-control evaluation, and DSP semantics.
- The process callback receives only fully built state and performs bounded work: no parsing, graph construction, allocation/deallocation by design, blocking locks, filesystem/console I/O, or UI work.
- Persistence, restore, Module installation, and render publication are failure-atomic.
- Active identity, diagnostics, graph/Parameters, History, transport, activity, safety levels, and render provenance remain inspectable.

## Responsibility chain

```text
project.crump + imported modules + declared WAV bytes
              |
              v
  lossless syntax grouping (dsl/syntax)
              |
              v
 recoverable typed parse (dsl/parser)
              |
              v
whole-Project validation (validate)
        |                  |
        | invalid          | valid + explicit publication
        v                  v
 diagnostics      atomic History snapshot + Active pointer
                           |
                 +---------+----------+
                 |                    |
                 v                    v
 schedule/control/graph compile   offline render
                 |                    |
                 v                    v
       preallocated SongRuntime   float WAV + manifest
                 |
                 v
        bounded PipeWire queue
                 |
                 v
      process callback + telemetry
```

The Candidate is current source bytes. The Active Revision is an exact committed snapshot. The two identities can intentionally differ while a musician inspects valid external work or repairs invalid source.

## Deep seams

### Source and model

`ProjectBundle` owns canonical root, sorted exact source bytes, verified immutable `AssetInventory`, byte-exact revision, recoverable model, and diagnostics. Asset-free Projects retain the original source-v1 revision domain; Projects with media add normalized path, exact length, and SHA-256 identities. Source-v2 asset usages identify wavetable, graph sample, and multisample roles; wavetable assets additionally retain exact mono frame length/count, normalization, and morph interpretation sites while WAV bytes remain the sole media authority. Filesystem Candidates load regular Project-owned files without symbolic-link traversal, while Active snapshots resolve declarations from History-owned exact bytes; both adapters feed one ordered module-assembly and Candidate-finalization implementation. All clients use this one seam rather than reparsing ad hoc. Parser Nodes retain byte ranges for exact values and whole declarations; arbitrary source is never regenerated from the model.

### Checked authoring

A structured operation resolves a durable domain ID, captures expected revision/range/literal, and produces a `CheckedReplacement`. `ProjectMutation` can additionally stage bounded exact asset writes/removals. The transaction rereads source and media under the Project lock, rejects stale/overlapping/unsafe/no-replace conflicts, and validates the complete in-memory source-and-binary overlay. `HistoryStore` then owns journal creation, the operation-specific write callback, checked publication, commit, finish-or-abort, and recovery ordering as one durable lifecycle. External import paths are inputs only; authoritative source receives a normalized `media/ID.wav` path and lowercase hash. Wavetable import uses the same atomic source-and-binary transaction and also authors complete bounded frame interpretation after validating exact mono shape. UI and CLI share the source-edit functions. Structured operations cover portable-media import/collection and durable Timeline Clips, Locators, arrangement-time transforms, Groove Templates, Pattern Variations, Parameter locks, Events, Automation, Instrument macro/Parameter values and route depth/bypass (including generated Instrument sections), mix controls, processor settings, durable bypass, and comment-preserving same-owner processor reorder without flattening procedural declarations.

### History and Active publication

`HistoryStore` serializes all mutation with one project-local file lock. Content-addressed source manifests reference immutable, verified media blobs under `.crump/history/assets/<sha256>` and can be reused by multiple action entries. Legacy sample-free schema-v1 snapshots omit the defaulted asset manifest and retain their exact revisions. Atomic Active state replacement is provisional until the final committed marker is durable. Startup recovery rolls back a state pointer without that marker, discards uncommitted metadata, and repairs interrupted source-and-media transactions to the complete pre- or post-commit state before returning a store.

### Musical runtime

`CompiledProject` recursively materializes acyclic Pattern Variations, inherited Parameter-lock timing, Groove-transformed Clip Events, stable Parameter targets, Automation points, instrument graphs, and one `CompiledMixGraph` off-thread. The authored model retains Variation lineage; callback code sees only bounded immutable schedules and lock lanes. `SongRuntime` is the shared mutable semantic machine for monitoring and rendering. It owns a preallocated `ControlRuntime`, fixed Track/voice/Node source state, and a `MixGraphRuntime` that executes Track, Group, Return, and Master channels in stable topological order. Ordered Instrument post chains, channel inserts, pre/post Sends, sidechains, gain/panner/Mute, convergence compensation, and Master processing all run through that graph.

`engine::graph` exposes only its crate-private compiled-graph, voice/shared runtime, work, and state-estimate seam. `graph::runtime` owns domain-aware topological lowering, per-voice lifecycle, and the Track-owned shared post-voice runtime; the closed `graph::nodes` implementation owns immutable Node programs, paired preallocated state, dispatch, DSP, and resource facts in oscillator, envelope, filter, and effects submodules. Program/state variants are created together; the legacy empty-signal fallback remains only as a callback-safe guard if an internal caller violates that pairing invariant.

Stable source version 2 preserves the complete version-1 graph floor while adding authored Bus IDs, exact ordered Node-setting sites, explicit typed mono/stereo conversion, stereo mixing, bounded stereo summing, one optional shared graph, Track-owned voicing, sound-neutral presentation metadata, Instrument Modulation, and runnable virtual-analog oscillator/stereo-filter/AHDSR/expressive-LFO programs. Legacy `connect` declarations receive deterministic IDs from a namespace disjoint from valid authored IDs; repeated stereo-sum inputs lower in durable Bus-ID order. Runnable `spectral` consumes a referenced-only immutable `crump-spectral-peaks-v1` analysis derived from the exact Project-rate sample cache: fixed 2,048-frame periodic-Hann windows at 256-frame hops retain at most 128 deterministically ranked stereo sinusoidal peaks per frame. Each graph voice owns one preallocated phase pair per admitted peak and bounded scan state; the callback linearly interpolates ranked frames, advances independent source time and repitched sinusoidal phase, applies frequency-region/transient/phase-randomization policies, and omits post-pitch frequencies above Nyquist. Analysis payload and callback work are preflighted before decode/FFT allocation, exact asset/sample/algorithm geometry forms cache identity, and generated inspection exposes identity and shape without retained peak payload. Runnable `granular` reuses exact decoded sample frames with one preallocated 1–64-slot pool per graph voice, sample-accurate bounded density scheduling, durable semantic Node/spawn identity, finite windows and arbitrary-overshoot edge laws, and a one-second maximum grain tail. Runnable `sample_source` and `multisample` Nodes reuse one exact-asset decode/resample library: only assets reached from Track-assigned Instruments materialize immutable Project-rate stereo frames, and preflight admission counts their converted payload before allocation. Each graph voice owns bounded cursor, gate-release, and selected-zone state; slice/zone regions remain exact original-source frames, rate is repitch-only, and semantic note identity selects precompiled round-robin groups without callback allocation. `wavetable` is runnable: each table referenced by a Track-assigned Instrument compiles off-callback into immutable level-major radix-2 mip data with a versioned hash identity over exact asset bytes, Project rate, frame metadata, normalization, and morph law; unused declarations allocate no derivative cache. Each callback lookup selects a Nyquist-bounded harmonic level, performs cyclic linear phase interpolation and declared inter-frame morphing, and uses only fixed subvoice state; asset/table/stage/allocation changes are structural transition facts. Compatibility hashing canonicalizes compiler-effective Node, scalar-setting, and stable-Bus order; workspace inspection projects topological Node and Bus-ID convergence order in both domains. Its generated Instrument view consumes optional authored presentation sections, fills every missing standard section, appends unassigned topology, exposes exact source sites, and delegates Parameter/route edits to the checked Production View boundary; presentation data is excluded from audio semantic hashes. Graph slot admission includes both stored voices, fixed held-note/voicing state, clip envelopes, analog/wavetable unison, sample/multisample region and zone work, granular fixed-pool work, spectral peak/phase work, and custom-LFO work, immutable boxed programs, conservatively charged decoded sample storage, shared wavetable mip storage, and shared spectral-analysis payload, crossfade/container overhead, both resident publication runtimes, and their combined transition-frame callback work.

Each Track executes active voice slots and accumulates their stereo outputs in stable slot order, then executes one separate shared runtime through exactly one typed `voice_sum.audio` Bus before the existing Instrument post-processor chain. Shared processing continues on silent sums so tails advance. Its Parameter workspace uses the per-Track singular projection and excludes every per-voice contribution. Pattern-lock schedules and projection buffers are keyed by durable Track ID; Song-global Parameter sources that would ambiguously read one of those locks fail validation. Global source state remains Song-shared; Instrument state and the shared Node/tail workspace remain isolated by durable Track identity. Shared work, heap state, signal/control/transition arrays, immutable programs, compatible handoff work, and both resident runtime slots are admitted explicitly. Shared topology participates in semantic transitions under ADR 0011 and ADR 0017, while an explicit seek clears shared DSP state off-callback before publication.

Every authored frame evaluates base → optional Automation → optional Pattern Parameter lock → Instrument-owned routes → separate Song-owned routes and Audio-derived contributions → constraint before graph and channel DSP. A lock is a Track-keyed step override scoped through its Clip traversal and resets at the Clip end; validation rejects overlapping Clips that would give one Instrument ambiguous lock precedence. Instrument-owned macro routes use a scope-compatible acyclic same-frame DAG and one stable signed-order/ID fold across scopes. Global source contributions execute once in Song control state but remain interleaved at their positions in that fold; Instrument sources use absolute transport phase plus durable per-Track identity; graph voices retain a separate note-on modulation clock through release and apply precompiled note-relative sources without callback allocation. Instrument/per-voice routes and both primary and auxiliary graph Envelope/LFO dependencies are operations in the combined graph/route schedule, so a Control source reaches downstream Parameter consumers on the same frame with no hidden cache delay. Compatible route-depth, bypass, and macro publications retain voices and ramp the affected Parameter/dependency closure through the preallocated 10 ms scalar handoff. Graph Instruments expose Track-local mono/poly allocation, held-note priority/fallback, deterministic stealing, velocity to amplitude/timbre paths, AHDSR/custom-LFO filter modulation, key tracking, central log-frequency glide, clean SVF multimode filtering, a 2×-oversampled driven ladder low-pass, and fixed-capacity stereo analog unison with seeded phase/drift plus typed FM/PM/sync/AM/ring. Note and transport LFO clocks share deterministic waveform/direction laws; synchronized graph periods compile against Song meter/tempo; custom-point interpolation is fixed at 64 points. Active graph-voice restart/replacement swaps into a second preallocated state slot and crossfades for 64 frames; all held-note, program, storage, and worst-case work enters admission. Offline mode fails on non-finite audio output; effective control holds its prior finite value on a non-finite result; monitoring adds only an explicitly non-authoritative audio safety stage. `engine::audition` resolves Song/Track/Clip/Pattern/Asset/Mapping/Occurrence IDs, filters a temporary compile model without changing source, prepares exact Musical Time/Locator ranges through deterministic preroll, and selects raw, mapping-source, Channel Strip tap, or Master output. Transient Solo/cue/bypass and pause use fixed callback-safe commands and are ignored by offline processing; exact seek publishes an already prepared runtime instead of doing unbounded callback work.

One native processor-semantics module resolves setting legality, physical domains, defaults, conditional EQ presence, Delay relationships, and effective ordering for validation, control compilation, DSP compilation, and inspection. Inspection adapts that shared meaning into effective settings, authored-literal and continuous-target provenance, authored/transient/effective bypass and continuing-state policy, current input/output/reduction activity, explicit/intrinsic latency, nonlinear evaluations, filtered oversampling factor/tap count, and admitted state/work estimates. Every processor runtime also owns a full-output-latency-aligned dry delay; bypass continues wet processing, monitoring-only transient toggles move through a fixed 64-frame guard, and durable bypass switches at its exact authored step frame in realtime and offline processing. Saturation and Limiter share one fixed 4×, 129-tap linear-phase FIR kernel: Saturation filters interpolation and decimation with an aligned 32-frame dry path, while Limiter uses the 16-frame reconstruction latency plus authored structural lookahead and a disclosed fixed 0.1 dB safety margin for inter-sample-peak detection and gain scheduling. Callback telemetry has fixed capacities for every compiled channel and processor; stable `(owner, processor-id)` indexes align telemetry with inspection across compatible publication and currently publish compressor gain reduction. Validation counts repeated Instrument post-chain runtime instances, separately preserves per-voice graph/Node allocations when shared processor state is recalculated, caps processor instances before allocation, and rejects settings or sidechain declarations/routes that the selected native kind does not consume. Utility mid/side narrowing has explicit correlation-safe semantics; EQ high/low cuts, shelves, and parametric bands have finite impulse, measured frequency-response, full-band inspection, and 64/128/256-frame processing-equivalence tests. The linked-stereo feed-forward compressor has explicit peak/RMS detector semantics, one-pole attack/release detection, a continuous soft-knee curve, parallel wet/dry mixing, wet-path makeup, and external-sidechain replacement; vectors and a source-backed kick/bass fixture verify its movement and telemetry. Delay resolves straight/dotted/triplet tempo divisions against the compiled Song tempo, uses interpolated read heads and preallocated time-change crossfades, filters feedback, and supports independent-stereo or cross-fed ping-pong operation; inspection publishes the effective synchronized time and exact admitted state. Reverb uses fixed preallocated stereo comb/gain-neutral-allpass networks with bounded feedback and diffusion, fractional-delay modulation, cross-fed stereo input, wet-side width, and a fractional one-second pre-delay ring with preallocated read-head crossfades; shared Return routing fans all Sends into one continuing processor state whose complete DSP heap is admitted before publication. `modulation_delay` owns one fixed ring and structural Chorus/Flanger modes behind shared typed controls; `crusher` separately owns intentional quantization/decimation/reconstruction semantics and the new physical `bits` unit. Inspection reports Project-bounded feedback tails or finite crusher tail frames. Gate/Expander reuses latency-compensated named sidechain routing, while finite Stutter owns one preallocated preceding-audio ring, structural musical durations, versioned absolute-cycle seeded triggers, and ignored-trigger telemetry. A separate typed Envelope Follower observes compiled channel taps after routing and schedules route-identified additive physical contributions for the next frame, preserving the controls-before-Audio order with explicit one-sample latency. The callback runtime Arc-shares immutable mix, control, schedule, Instrument graph programs, decoded/resampled sample frames, and compiled wavetable tables instead of deep-cloning them. Admission separately counts those programs' owned capacities (including scheduled Event identity strings), the complete `SongRuntime`/Track/control/mix container backing, graph, sampler, and stock-drum voice vectors, authored Nodes plus lowered modulation/Song-tier operations, route-control and transition arrays, unison subvoice work, graph replacement-tail storage/work, machine-word-rounded packed Boolean storage, processor-program clones, auxiliary storage, the two resident old/new publication slots, and the conservative combined old/new callback work plus bounded handoff bookkeeping. These are conservative owned-capacity estimates; allocator-private metadata is not claimed as byte-exact.

### Finalized delivery analysis

`engine::analysis` is the single delivery-measurement seam. It reopens a finalized stereo float WAV, validates its exact format and declared frame count, streams decoded samples through fixed K-weighting and the shared custom 4× reconstruction kernel, and returns a versioned `FinalizedAudioAnalysis`. Analysis schema 2 evaluates integrated 400 ms blocks and three-second Short-term windows at 100 ms hops; Loudness Range derives its `−20 LU` relative gate from the absolute-gated Short-term population before nearest-percentile selection. Sample/reconstructed peak, BS.1770/EBU-derived loudness, per-channel DC, clipping, and non-finite facts therefore describe written bytes rather than transient bus telemetry. `engine::render` rejects non-finite or frame-inconsistent analysis before writing the manifest. Silence and insufficient windows remain explicit `null` values; analysis never normalizes Audio or imposes a universal LUFS target. Published EBU steady-tone vectors are covered, but complete EBU Mode or BS.1770-5 conformance is not claimed.

`engine::qualification` is a separate offline workload-measurement seam. It compiles the exact Active snapshot, prerolls untimed to an explicit frame range, and times supported full-size engine blocks plus one disclosed short final block when needed. Every invocation uses its exact frame deadline; fixed-histogram overflow conservatively reports the observed peak. Its versioned report binds Project Revision, executable/host identity, range, full/final block sizes, finite output, compile-time admission resources, automated repository checks still required beside the report, and genuinely external evidence still required. Atomic report output cannot overlap source, declared media, or `.crump` History. `qualify --require-pass` preserves the completed report before returning a failed gate. PipeWire xruns remain absent because this seam does not measure the realtime graph or device scheduling; warmed callback allocation/deallocation is separately tested at the private `CallbackState` seam, with maximum-topology steady-state/control handling distinct from publication transition and deferred reclamation.

The mix runtime retains fixed-capacity current pre/post tap samples without allocation. Render planning resolves each selected durable Track/Group owner to that dense tap, computes initial padding as `Master output latency − selected channel output latency`, and freezes an explicit processing policy. Both taps include upstream main routing and owner inserts; post-fader also includes owner gain/panner/Mute; outgoing Sends and downstream Group/Return/Master processing remain outside the file. Tap blocks spool to raw staging shards of at most 16 Stems, then one shard at a time streams into at most 16 alignment-aware WAV writers. This bounds both open descriptors and memory instead of retaining a file or full latency buffer per Stem. Master and every Stem receive the same frame count and tail, then each file is independently finalized, synced, analyzed, and hashed before one directory exchange publishes the exact artifact set. Existing-bundle replacement revalidates manifest names, regular-file status, policy, format, frame count, every hash, and a fresh finalized-file analysis against the manifest. A 192-Stem maximum-topology fixture and a post-spool failure injection cover descriptor pressure, destination preservation, and handled-failure staging cleanup.

### Native publication

The controller compiles and deterministically prerolls every explicit audition seek away from PipeWire, including retained target/range/path and transient bypass/Solo/cue state. For ordinary source publication it prepares from the latest observed range offset, but the callback—not stale UI telemetry—maps its exact publication-time offset or loop phase into newly resolved bounds (clamped only if the range became shorter). A mapped absolute-frame jump does not adopt processor state from the different old timeline point; unchanged absolute positions may use the existing semantic handoff. The callback can pause without advancing or destroying runtime state and continues draining resume/Stop controls even while a publication transition is resident. One atomic admission slot is reserved before candidate runtime allocation, so the process retains at most the Active runtime plus one queued or transitioning replacement; when that slot is busy, the workspace retains the newest Active revision and retries after transition telemetry clears. The callback performs only bounded cursor realignment or an explicit prepared-seek swap through an SPSC ring and begins a bounded 10 ms transition at a block boundary; it neither sweeps large DSP buffers nor constructs or drops callback-owned heaps. A wholly topology-compatible routed publication processes each Track source, Track-owned shared post-voice graph, and Song MixGraph channel path once, retains compatible voice/shared/processor/compensation state, and applies a preallocated monitoring-only ramp only to changed continuous effective targets; unchanged step/linear Automation remains sample-exact and boolean Mute remains discrete. Raw-source publication realigns the replacement cursor to the callback-resolved absolute or range-relative target and advances both sides through the bounded crossfade, because raw output does not flow through the shared mix graph. Configuration or topology changes use the equal-power old/new fade rather than unsafe state adoption. Retired runtime destruction is returned through another ring before the publication slot reopens. This realizes [ADR 0011](../adr/0011-graph-transition.md) without universal semantic smoothing or transport restart. Incompatible topology state is not migrated.

### External Agents

No model runtime is linked into Crump. Agents read source and use `inspect`, `validate`, checked `edit` operations (including Timeline, Groove, Variation, lock, Automation, and media transforms), explicit `publish`, History, Module, and render commands through one JSON envelope ([ADR 0005](../adr/0005-external-authoring-agent-boundary.md)). Agent rationale becomes durable provenance; invalid work remains Candidate-only.

## Determinism and failure boundaries

Deterministic identity is semantic where ordering should not matter (Events, seeds, topological schedule) and byte-exact where authorship must remain reviewable (source/media revisions and snapshots). Rendering records Project/build/platform/frame identity and hashes every artifact. Byte comparison is bounded to the declared build and documented Linux `x86_64` comparison domain.

Every irreversible seam stages and fsyncs before an atomic rename or exchange. The observable states are the complete old state or complete new state.

## Unsupported boundaries

Media Tracks, recording, realtime routed pitch, formant-preserving processing, plug-in hosting, native extensions, incompatible topology state migration, and non-Linux playback clients are unsupported.
