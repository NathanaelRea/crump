# Architecture Decision Records

Create an ADR only after a consequential, hard-to-reverse tradeoff has been resolved.

Use sequential names such as `0001-authoritative-project-source.md`. Every ADR includes a title and a concise statement of what was decided and why. Add only the sections that preserve useful context:

- Status and date.
- Context and decision drivers when the trade-off is not obvious.
- Consequences when they constrain later work.
- Alternatives when a reasonable rejected option is likely to recur.
- Durable evidence links when evidence exists in the tracked repository.
- Superseded or superseding records, when applicable.

Product scope belongs in the product contract, not in an ADR.
