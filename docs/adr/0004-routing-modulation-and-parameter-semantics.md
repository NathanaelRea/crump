# ADR 0004: Routing, Modulation, and Parameter Semantics

Status: Accepted
Date: 2026-07-26

## Context

Crump needs one source-readable model for timeline processing, reusable DSP graphs, mixer routing, sidechains, automation, modulation, live editing, and offline rendering. DAW terms such as group, return, and bus overlap in common usage, while hidden channel conversion, parameter normalization, control-rate behavior, or latency policy would undermine deterministic playback and portable projects.

## Decision

- The compiled project is an acyclic graph of Processing Nodes with named typed Ports and Buses. Ports carry Event, channel-layout-aware Audio, or unit-typed scalar Control streams in one sample-time domain. Input cardinality is single, optional, or explicitly summing; incompatible signal units or Audio layouts require explicit conversion nodes. Sidechains are named auxiliary Audio inputs, not a separate routing mechanism. Intentional feedback is encapsulated by an explicit bounded stateful device.
- Authored DSP graphs are hierarchical reusable definitions with typed interfaces. Internal nodes have definition-local Durable Domain IDs; runtime identity composes the enclosing instance-ID path with the local ID even if compilation flattens the graph.
- Track, Group, Return, and singleton Master are distinct channel roles. Group membership requires a member's main output to pass through its parent Group. A top-level Track or Group defaults to Master. A Return receives durably identified Sends, defaults to Master, and may instead feed a Group or later Return if the graph remains acyclic. Bus names the typed routed signal, not another channel kind, and timeline Tracks cannot act as ad hoc main-output buses.
- A Send targets exactly one Return and independently selects a pre-fader or post-fader tap. Every Track, Group, and Return sums inputs, runs ordered inserts, exposes the pre-fader tap, applies gain and an explicit panner mode, applies mute, exposes the post-fader tap, then routes its main output. `mono_pan` uses equal-power mono-to-stereo placement, `balance` attenuates stereo sides without crossfeed, and `stereo_pan` positions the two input sides independently using the mono law.
- A Parameter is identified by its owner's durable or intrinsic identity plus an immutable owner-defined key. Kinds are continuous real, bounded integer, boolean, and enum. Parameters declare domains, defaults, physical units, display mappings, and Automation/Modulation capabilities; source never stores adapter-normalized values. Authored out-of-domain values invalidate the Candidate Revision. Runtime Modulation overshoot clamps, and non-finite Control holds the last finite effective value with a diagnostic.
- Effective values evaluate in a fixed order: base value, one optional Song-scoped absolute Automation function, one optional active Pattern Parameter lock, additive Modulation routes in stable identity order, then domain constraint. Point Automation starts at Song time zero, has unique increasing points, holds its last value, and explicitly uses `step`, `linear`, or `power(p)` per segment in canonical units. For `power(p)`, `p > 0` and `v(x) = a + (b - a) * x^p`. Integer, boolean, and enum Automation is step-only. A Pattern lock is a durable physical-unit step override scoped through one Clip traversal; it follows looping, source offsets, and procedural Pattern timing, then resets at Clip end. Lock targets must be topology-stable and automatable. Overlapping Clips that share an Instrument are rejected when either contains locks, so runtime precedence is never inferred from Track or source order.
- Continuous reusable Pattern, envelope, and LFO control reaches Parameters as Modulation rather than competing absolute Automation; the narrow step-lock contract above is the deliberate exception. Modulation sources declare normalized unipolar `[0,1]` or bipolar `[-1,1]` output; every route declares depth in the target's modulation unit. A route transforms only its normalized source through authored operators in declaration order: `add` and `bias` add a unitless scalar, `multiply` and `scale` multiply by one, and `clamp` applies inclusive normalized bounds. The transformed value is multiplied by physical-unit depth; routes then fold additively in durable route-ID order. A non-finite intermediate makes the complete target result non-finite so the prior finite effective value is held. Global and Instrument LFO phase follows absolute transport time; per-voice phase resets on note activation. Free rates are cycles per second and synchronized rates declare the exact musical duration of one cycle. Continuous Automation and Modulation are sample-accurate and block-size-independent. The host does not add universal smoothing; node-owned smoothing is deterministic DSP behavior shared by playback and rendering.
- Every node output declares deterministic sample latency for its active configuration. Compilation compensates Event, Audio, and Control paths at every convergence so all inputs represent the same source time, including parallel, Send, Return, sidechain, and cross-domain paths. A latency change produces a new Candidate Revision.
- Mute is source-backed, step-automatable project state. Solo, cue, and monitoring are transient Audition State and do not affect offline rendering. A non-authoritative safety stage sanitizes and emergency-limits real-time output after Master; offline rendering bypasses it, fails on non-finite output, and is limited only by explicit authored Master processing.

## Consequences

The DSL and compiler must expose routing, conversion, identities, units, interpolation, and latency rather than infer them from source position or device convention. The model gives graph replacement and state migration stable targets, makes sidechains and parallel processing ordinary typed routing, and keeps rendering independent of block size and workspace audition controls. It deliberately rejects arbitrary routing cycles, implicit channel coercion, normalized authored parameters, ambiguous overlapping lock-bearing Clips, generic Track-as-bus behavior, and hidden host smoothing.

## Alternatives Considered

Separate Group, Return, and Bus channel kinds; fully generic channels whose topology alone determines their role; arbitrary delayed routing cycles; implicit Audio conversion and fan-in; normalized or device-defined Parameter values; unrestricted control graphs; ambiguous clip-automation or Parameter-lock precedence; partial latency compensation; and persistent Solo state were rejected because they create hidden or unstable semantics, weaken static validation, or make playback and rendering diverge.
